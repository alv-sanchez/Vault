## Polish (build-fleet run)

_2026-06-12, CART-4051 worker. Key finding that supersedes both the scope report and Validation Run 0: the ADR-0010 promotion resolver is NOT deferred anymore — `S_PriceResolver` (OHFY-OMS/.../services/priceResolver/, 602 lines, + global DTOs CartResolutionRequest/LineRequest/CartResolutionResult/LineResult) merged to main 2026-06-11 under BMS-3876 (#286, e4cc770c). ### Residual ACs (buildable now)

1. **Server-side cart pricing seam** — new `Ecom_UI_Wrappers.resolveCartPricing(Id accountId, Id fulfillmentLocationId, List<LineRequest> lines)` returning `CartResolutionResult`, delegating to `S_PriceResolver.resolve()` (mirrors the existing `resolveCatalogPricing` → `S_FrontLinePricing` precedent in the same class, line 378). Verifiable: Apex `_T` delegation test + deploy validate.
2. **Volume-tier recalculation on quantity change** — ecomCartPage triggers a debounced cart-wide server reprice whenever a line quantity changes; QD tier selection is evaluated server-side against cart-context quantity, and the line's displayed unit price/subtotal/savings update when the quantity crosses a tier threshold. Verifiable: Jest test + Playwright spec with seeded QD promo.
3. **Multi-promo handling** — when several promotions target the same line, the server's priority-winnow + deepest-discount pick is what the cart displays (replaces the client-side "first promo in array" heuristic as the price authority). Verifiable: Apex `_T` multi-promo test (already in S_PriceResolver_T) + cart stamps `promotionId` from LineResult.
4. **Per-line pricing isolation** — every cart line's price comes solely from its own LineResult (positional/itemId mapping); a promo on item A never alters item B's price. Verifiable: Jest test with a 2-line cart where only one line has a promo.
5. **Graceful degradation** — lines with `flpResolutionPath = NONE` or no winning promo keep base behavior; a resolver call failure leaves the existing client-side estimate in place (cart never blanks), error logged to console. Verifiable: Jest failure-path test.
6. **Promo demo seed script** — `orgScripts/e-commerce/seed-promo-demo.apex` (+ revert) mirroring seed-flp-demo.apex (/Users/alvarosanchez_1/Documents/Obsidian/Vault/Anvil/Engineering/Sprints/Visuals/front-line-pricing-data-model.html): one QD promo with tiers + one Post-off promo + Promotion_Group/Account_Promotion_Group junction for the ecom test account. Closes the "no seed data for volume tiers/promotions" gap.
7. **Tests ride the gates** — `Ecom_UI_Wrappers_T` addition runs green on ecom-cart; full Jest green; new `test-automation/tests/ecom/cart-volume-tiers.spec.ts` (skip-guarded on promo seed data presence) green on ecom-cart.
