BMS-4053Volume Tier

Cart-Context Summing — Worked Examples

The subtle part of the tier sub-layer: a QD's quantity threshold is tested against the summed quantity of every in-scope cart line, not any single line. Seven traces against the seeded demo, each grounded in the real resolver code. Companion to BMS-4053-pricing-priority-walkthrough.html.

0The demo promotions

QD (Volume) · scope = ITEM_TYPE: Sharks Fin · Dollartier@10 → −$3 · tier@50 → −$6
Post-off · scope = ITEM: Wave Splitter 1/6 BBL · Dollar−$10 · Min_Quantity 1
Sharks Fin basesCase $17 · 1/6 BBL $60 · 1/4 BBL $70 · 1/2 BBL $160

How the engine works, in two functions:

// 1 · For EACH eligible promo, sum every cart line whose item matches its scope.  S_PriceResolver.cls · L396–413
for (Promotion__c promo : eligible) {
    Decimal total = 0;
    for (LineRequest line : lines) {
        Item__c it = itemsById.get(line.itemId);
        if (it != null && scopeMatches(promo, it) && line.quantity != null)
            total += line.quantity;            // ← cart-context sum, NOT per-line
    }
    qtyByPromotion.put(promo.Id, total);
}

// 2 · QD picks the HIGHEST tier whose Min_Quantity is still ≤ that summed qty.  S_PriceResolver.cls · L322–342
for (Promotion_Tier__c tier : tiers) {
    Decimal tierMin = tier.Min_Quantity__c == null ? 0 : tier.Min_Quantity__c;
    if (cartQty < tierMin) continue;            // not unlocked
    if (best == null || tierMin > bestMin) { best = tier; bestMin = tierMin; }
}
if (best == null) return null;                  // no tier → no QD win → Frontline
amount = best.Discount_Amount__c;  tierId = best.Id;   // tierId set ⇒ "Volume Price"

In one paragraph: cartContextQuantities builds a Map<promotionId → summed-qty> by adding every cart line whose item is in that promo's scope. For a QD, applicableDiscount keeps the tier with the highest Min_Quantity__c still ≤ that sum, and stamps its tierId. Same brand, mixed packaging, spread across lines — it all pools into one threshold. The deeper the pool, the deeper the tier; the instant a tier is chosen, promotionTierId is non-null and the storefront says "Volume Price."
Future-state caveat. This per-promo, raw-quantity summing is one of the likeliest spots for the canonical resolver to change — e.g. whether mixed packaging should pool at all, or whether tiers should evaluate case-equivalent volume rather than raw line.quantity. The code today sums raw line quantities (L407). The layering and priority model hold regardless; this specific aggregation rule is the soft edge.

3Two different "winners" — threshold vs. deepest discount

A common confusion: "the deeper tier won because it had the bigger discount." It didn't. There are two separate selection mechanisms, and only one of them looks at the discount amount.

Mechanism 1 · Tier pick — selected by THRESHOLD, not discount

30 × Case + 25 × 1/4 BBL → sum 55 (one QD in scope)

Inside applicableDiscount, the only comparison is on Min_Quantity__c:

for (Promotion_Tier__c tier : tiers) {
    tierMin = tier.Min_Quantity__c;
    if (cartQty < tierMin) continue;
    if (best == null || tierMin > bestMin) {   // ← Min_Quantity, NOT discount
        best = tier; bestMin = tierMin;
    }
}
amount = best.Discount_Amount__c;            // −$6 read only AFTER winner is fixed
tier@10: 55 ≥ 10 ✓ → bestMin 10  ·  tier@50: 55 ≥ 50 ✓ and 50 > 10  → best = tier@50
// the single Qualified this produces — tier@50 chosen by threshold
{ "promotionId": "a3Yed000000Qd001", "tierId": "a3Zed000000Tr50", "perCase": 6, "priority": null }
Proof it's threshold, not discount — misconfigured tiers: if tier@50 were authored at −$2 (smaller than tier@10's −$3), at qty 55 the loop still picks tier@50 (50 > 10) → you'd get $17 − $2 = $15, the worse deal. The resolver never rescues you with tier@10. Tiers must be authored monotonically; nothing validates it.

Here the discount amount IS the selector — but only because two different promotions compete for one line. That's Layer 2 · Stage 5, distinct from picking a tier inside a single QD.
The contrast in one line. Same QD, many tiers → pick by quantity threshold (deeper tier assumed to carry a bigger discount, never checked). Different promotions, one line → pick by deepest perCase via isBetterForCustomer — unless a Priority__c winnow already eliminated the cheaper one first.
