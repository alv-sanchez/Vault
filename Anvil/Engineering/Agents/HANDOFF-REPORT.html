What this project was

A Workflow-tool orchestration that takes a Jira epic (BMS-4995, the Gulf retailer Experience Cloud storefront) and drives its tickets to reviewed, test-green PRs with near-zero human babysitting. The design: group tickets into domain lanes, claim one scratch org per lane from the CI pool, run lanes in parallel and tickets sequentially within a lane, each ticket getting its own git worktree → polish → implement → test → draft PR → docs. A shared Obsidian "context bucket" was the only cross-agent communication channel; the orchestrator mediated everything else.

It ran in distinct phases: Scope (10-agent fan-out grading every ticket), Validation Run 0 (8-agent duplicate-work + lane-fit sweep), and the Build fleet (3 lanes, org-per-lane, polish-and-build per ticket). A human (Alvaro) ran one ticket — BMS-4258 — manually in parallel as the learning template for Experience Cloud development.

Where it stopped & why

The build fleet hit the org monthly spend limit mid-run (2026-06-12), killing 5 ticket agents at launch. A post-reset resume completed CAT-4054. The work then paused for the model sunset. Honest accounting: 4 human interventions total across the whole project (workflow args bug, two scope re-cuts, the 3932 PO rulings) — plus the spend-limit halt. No half-finished worktrees were left in a broken state; agents that died died before creating their worktree.

How a successor resumes

  • Source of truth: ORCHESTRATION_HANDOFF.md (architecture, decisions, "Hold state & resume") and QUEST_NOTES.md (evidence log) on branch fable-project-as; this report + the Agents/ bucket in Obsidian.
  • First moves on resume: (1) deploy the sharing-rule fix to unblock CART write paths; (2) fix the #293/#296 deploy-delta CI; (3) get the PO answers for BMS-4052 and confirm BMS-3932 v1 scope; (4) commit the two uncommitted skills so future worktrees inherit them.
  • Then: re-launch the build script (saved under the session's workflows/scripts/) trimmed to the 4 remaining tickets, or run them by hand using the same lane orgs.
  • Caveat: the /document skill ecom-auth fix made here was superseded by upstream (#298 added the storefront capture branch + ecom SKU officially) — use main's version.

What worked / what to keep

Worked

  • Validation-before-build caught duplicate work that would have wasted the whole fleet.
  • Org-per-lane + sequential tickets — no org contention, clean parallelism.
  • The "already shipped, do NOT rebuild" inventory kept agents honest and scoped.
  • Agents escalated real coin-flips (tax rules, brand field, security deploy) instead of guessing.
  • One fully-green PR (#294) end-to-end with docs, hands-off.

Friction

  • Spend limit is the hard ceiling — a 7-ticket fleet exhausted it in ~84 min.
  • Shared-worktree .env contention between lanes (logged in org-issues).
  • Pool orgs lack some features (AccountContactRelation, Twilio cred) vs the snapshot.
  • The cross-reference sharing bug is a real product gap surfaced by automation, not a test artifact.
