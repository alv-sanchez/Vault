Relating a Contact to Multiple Accounts

Salesforce admin guide · For admins / ops setting up the ecom account switcher (BMS-4258) · Uses native Contacts to Multiple Accounts

Goal: link one contact to several businesses so the storefront account switcher shows them — and know how to confirm the data is right. No custom objects; this is Salesforce's built-in AccountContactRelation.

The model

Contact "Ecom Tester"
   ├── AccountId = Customer Account 0        ← PRIMARY account (a "direct" relation)
   ├── AccountContactRelation → Dixie Bar & Grill       (indirect)
   └── AccountContactRelation → Riverside Bottle Shop   (indirect)
  • Every contact has exactly one primary account (Contact.AccountId); Salesforce auto-creates its AccountContactRelation with IsDirect = true.
  • Each additional business is a separate AccountContactRelation with IsDirect = false.
  • The switcher lists every active related account (direct + indirect).

Step 1 — Enable the feature (one-time, per org)

Setup → Account Settings → Edit → check "Allow users to relate a contact to multiple accounts" → Save. This creates the AccountContactRelation object.

Scratch org caveat: the checkbox only works if the org was created with the ContactsToMultipleAccounts feature in its scratch definition. The box can read "checked" while the object still doesn't exist. Production/sandbox orgs need only the checkbox.

Step 2 — Make the related lists visible (one-time, per layout)

  • Setup → Object Manager → Contact → Page Layouts → drag the "Related Accounts" related list onto the layout → Save.
  • (Optional) Object Manager → Account → Page Layouts → add the "Related Contacts" related list.
Why a related contact isn't under "Contacts": the standard Contacts list only shows contacts whose primary account is that account. Indirect relationships appear under Related Contacts. Expected behavior, not a bug.

Step 3 — Relate the contact to more businesses

From the contact (recommended):

  1. Open the Contact record.
  2. On Related Accounts, click Add Relationship.
  3. Pick the Account, optionally set Roles, Save.
  4. Repeat for each additional business.

From the account: Account → Related Contacts → Add Relationship → pick the contact. The primary (direct) relation is created automatically — don't re-add it.

AccountContactRelation field reference

FieldMeaningFor the switcher
ContactIdThe contactWho is related.
AccountIdThe related businessOne per relationship row.
IsDirecttrue = primary account; false = additional businessDirect one is marked primary; both appear.
IsActiveWhether the relationship is activeOnly active relations are listed. Set false to hide without deleting.
RolesMulti-select (Decision Maker, Buyer, …)Optional; not used today.
StartDate/EndDateValidity windowOptional; informational.
  • No duplicate Account+Contact pairs allowed.
  • You can't delete the direct relation directly — change the contact's primary account instead (the old primary becomes indirect).
  • Deactivating (IsActive = false) is the soft way to remove a business from the switcher.

How to verify it's set up right

A · In the UI

Contact → Related Accounts shows all businesses (primary marked direct, plus each added one). A secondary Account → Related Contacts shows the contact (it will not be under plain "Contacts").

B · Via SOQL

Scoped to one contact:

SELECT Account.Name, IsDirect, IsActive
FROM AccountContactRelation
WHERE ContactId = '<contact id>'
ORDER BY IsDirect DESC

Expect one IsDirect = true (primary) and one per additional business (IsDirect = false), all IsActive = true.

Full field set (every relationship in the org — useful for an admin audit):

SELECT Id,
       AccountId, Account.Name,
       ContactId, Contact.Name, Contact.Email,
       IsDirect,
       IsActive,
       Roles,
       StartDate, EndDate,
       CreatedDate, LastModifiedDate
FROM AccountContactRelation
ORDER BY IsDirect DESC, Account.Name

Note: there is no Name field on AccountContactRelation itself — use the relationship fields Account.Name / Contact.Name. Roles is a multi-select picklist (semicolon-delimited string, or null).

C · In the storefront (end-to-end)

Log in as the community user for that contact. Desktop nav shows the active business (dropdown when multiple); mobile hamburger shows a "Switch Business" dropdown. Switching reloads the storefront scoped to the selected business.

Visibility requirement: the community user must be able to read an indirectly-related Account to open it. AccountContactRelation links them but does not grant record access — the ecom setup sets the external Account org-wide default to Read/Write. If a switch shows blank/placeholder data, check Account sharing for the community profile.

"Related Accounts" list missing on the contactAdd it to the Contact page layout (Step 2).
