Inbound-to-Replenishment: the user journey, tied to its LWCs

Happy-path journey from a supplier shipment through blind receiving to the Replenishment Engine and worker queue — with the claim branch, the actors who operate each step, and the exact Lightning Web Components and Apex that implement each screen. Anchor component: replenishmentTaskManager.

Captured July 17, 2026 — whiteboard + journey-dictation session Repo OHFY-Split · OHFY-WMS-UI / OHFY-WMS Status Happy path documented · claim journeys pending

The flow

Redrawn from the whiteboard. A purchase order is fulfilled by a supplier shipment and blind-received — the person unloading the truck counts product without seeing the PO quantities. The Floor Manager compares the PO to the blind receive: a clean match generates the Inventory Receipt (the invoice the distributor owes the supplier), which feeds the Replenishment Engine and its worker queue. A large enough discrepancy branches into a Claim instead.

Anchor component: replenishmentTaskManager

The warehouse-lead board (BMS-4219, Phase 2 prioritization BMS-4103). Pick a warehouse, clear the prior shift's tasks, generate a fresh days-on-hand / capacity-driven pool, then assign tasks to workers — this is the hinge between the Replenishment Engine and the pickers' Worker Queue.

How the board reads

Tasks group into three engine-computed risk lanes, each sorted by Priority_Value descending. Every card carries a velocity chip (units/day). Supervisors re-rank with ▲/▼ within a lane only — cross-lane moves have no meaning against computed risk bands (drag-and-drop was removed for that reason).

Behaviors worth knowing

  • Shift key is computed client-side as YYYY-MM-DD-AM|PM — the board, clear, and generate calls are all scoped to warehouse + shift.
  • Month-end freeze: “Generate New Task Set” and “Recalculate Priorities” are suspended while frozen; “Clear Prior Tasks” stays available. The freeze state and message come back on the board DTO.
  • Clear Prior Tasks reports how many tasks were cleared and how many were interrupted mid-pick.
  • Manual re-rank writes a Priority_Value just past the adjacent card and commits it as a manual override via overrideReplenishmentTaskPriority, then refreshes the board.
  • Assignment is multi-select checkboxes + a worker picker; guard rails toast if either side is missing.
  • Mobile: FORM_FACTOR === "Small" switches to a stacked single-column board with full-width controls and ≥44px tap targets (the ohfy-mobile root modifier).
  • Styling loads the WMS Tailwind static resource (tailwindCSS_wms) and degrades gracefully if it's slow; band colors ride the --ohfy-* design tokens.

Apex contract (via WMS_UI_Wrappers)

LWCs can't call @AuraEnabled methods in sibling managed packages directly, so every call proxies through the WMS_UI_Wrappers class into the OHFY-WMS engine (E_ReplenishmentTask, E_ReplenishmentConfig, E_ReplenishmentReasonCode, E_ReplenishmentTriggerEvent).

Open items

Not yet documented
  • Claim journeys. The session notes explicitly flag “we also have claim journeys to add” — the Front Office Worker's path from discrepancy → filed claim → resolution has no experience mapping yet.
  • Discrepancy threshold. “Large enough to warrant a claim” is human judgment today; no configured tolerance is referenced in the notes.
  • Replenishment Engine internals. The dictation cut off at “Replenishment Engine + worker queue:” — engine trigger conditions (IR-driven vs. scheduled vs. DOH threshold) should be confirmed against E_ReplenishmentTriggerEvent before this doc is treated as complete.
  • Replenishment Config is still UAT-pending; the exec-facing tuning journey may shift.
  • Missing masterLabels. Four receiving-side components (dockDashboard, receiverHomePage, blindReceivingFlow, receivingManagerView) are exposed to App Builder without a <masterLabel>, so admins see raw camelCase API names in the palette. Easy polish gap to match the replenishment trio.
  • Label drift. replenishmentConfig's masterLabel is “Replenishment Configuration,” while the experience sheet calls it “Replenishment Config” — align one to the other.
