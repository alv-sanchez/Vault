Default behavior is earliest-expiration first (FEFO), with the option to override and split across lots. Ships on both the pick path (BMS-5523) and the replenishment worker queue (BMS-5703). Additive only — no schema changes, no released signature breaks.

🎯 What it covers

Code-date selection at pick

E_PickPath.getPickStops prefetches eligible lots (FEFO, active, not-past-code-date, null-expiration last) onto each lot-tracked stop in one bulk query. Single active lot renders read-only; 2+ lots open a confirm panel defaulted FEFO, override/split/clamp-able. E_PickPathFulfillment honors the picker's chosen lotMoves — validated + aggregate-clamped per lot — with empty/null falling back to unchanged FEFO.

Default code-date selection at replenishment

LWC-only — the FEFO/completeTask(lotMoves) plumbing already shipped. Single eligible lot is read-only; 2+ lots expand by default with the full quantity pre-allocated FEFO to the earliest, reassignable/splittable by the worker.

Persistent zone-completion badge

Reviewer feedback: a fully-handled zone (picked/short/broken/skipped) only surfaced via a one-shot toast on re-entry. getPickZones now returns a server-computed isComplete flag, and pickPathAssignments shows a persistent "✓ Complete" badge on the zone card.
