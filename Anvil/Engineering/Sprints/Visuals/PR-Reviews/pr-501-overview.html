Key Decisions

  1. Hard human gate before any code. Phase 2's Productization Map (package targets, field-level rename table, component mapping, platform risk flags) must be explicitly approved by the user before a single product line is written — the skill treats demo code as a spec, never a paste source.
  2. Field renames ≠ prefix strips. The translation guide calls out that demo orgs run older package vintages, so ohfy__Active__c may map to Is_Active__c — stripping the namespace is necessary but not sufficient; every field is verified against current product metadata, with two grep sweeps at the end.
  3. Delta-port awareness. Acquire checks for an existing prior port on main and pivots to porting only the delta rather than re-porting the whole feature.
  4. Org-only schema classification. Schema present in neither repo is flagged as "org-only" and resolved by describe against the connected demo org, rather than silently assumed.
  5. Validated by self-application. The skill was hardened across three rounds against real Sales-Demos PR #2 (956 files) — baseline, dry-run, and a full live delta port — with the ~11 findings folded back into the skill and this CLAUDE.md change.

49+## Why demo code can't be copied
50+
51+Sales-Demos is unmanaged code written *inside customer orgs that have the ohfy managed package installed*. It systematically differs from product code:
52+
53+| Demo code | Product code (OHFY-Split) |
54+| --- | --- |
55+| References managed schema WITH prefix: `ohfy__Route__c`, `ohfy__Order__c` | Source is unprefixed within the namespace: `Route__c`, `Order__c` — strip the prefix AND verify the field still exists under that name (demo orgs run older package vintages; names drift: `ohfy__Active__c` → `Is_Active__c`) |
56+| Raw `[SELECT ...]`, raw DML, `Database.*` | `QueryService` / `DmlService` only (see `docs/security/mode-selection.md`) |
57+| Ad-hoc triggers or trigger logic in controllers | Trigger framework: `{Object}TriggerService` + `Trigger_Configuration__mdt` |
58+| `FooControllerTest` naming, `insert` test data | `Foo_T` naming, `TestDataFactory.createSObject()`, `TestService` bypass |
59+| Flat `classes/` per feature folder | Role directories with prefixes: `executables/E_`, `services/S_`, `controllers/`, `DTOs/<domain>/`, `wrappers/` |
60+| Un-instrumented catch blocks, `System.debug` | `Logger.getInstance().error(...)` + `flush()` in every catch; no `System.debug` |
61+| Per-customer folders (`TBM/`, `Ozone/`) each holding many cross-referencing feature folders | Split across tiers: objects → Data-Model, logic → domain package, LWC → UI package, cross-package via DTO/`@namespaceAccessible`/UI-wrapper facade |

1+# Demo → Product Translation Guide
2+
3+Read this before porting any file (Phase 3 of `productize-demo`). Each section shows the demo pattern and its required product form. Authoritative sources are linked — when this guide and a linked doc disagree, the doc wins.

5+## 1. Namespace prefixes AND field renames
6+
7+Demo orgs have the `ohfy` managed package **installed**, so demo code references managed schema with the prefix. Product source lives *inside* the namespace and is unprefixed. **Stripping the prefix is necessary but NOT sufficient** — demo orgs run older package vintages and field names drift, so every stripped name must be verified against current product metadata.
8+
9+| In demo code | In OHFY-Split source |
10+| --- | --- |
11+| `ohfy__Route__c`, `ohfy__Order__c.ohfy__Status__c` | `Route__c`, `Order__c.Status__c` |
12+| `ohfy__Route__c.ohfy__Active__c` | `Route__c.Is_Active__c` — a **rename**, not a strip |
13+| `ohfy__Day_of_Week__c` | `Day_Of_Week__c` — case differs; `@salesforce/schema` imports and metadata refs are case-sensitive |
14+| `@salesforce/schema/ohfy__Route__c.ohfy__Name__c` (LWC) | `@salesforce/schema/Route__c.Name__c` |

19+2. Every demo field name from the rename table's left column — nothing (`grep -rn "Active__c" ...` style spot-checks for the risky renames).

21+## 2. SOQL → QueryService
22+
23+```apex
24+// DEMO
25+List<ohfy__Route__c> routes = [
26+ SELECT Id, Name, ohfy__Status__c FROM ohfy__Route__c
27+ WHERE ohfy__Delivery_Date__c = :deliveryDate ORDER BY Name
28+];
29+
30+// PRODUCT
31+List<Route__c> routes = (List<Route__c>) QueryService.newBuilder(
32+ new List<String>{ 'Id', 'Name', 'Status__c' },
33+ 'Route__c'
34+ )
35+ .filters(new List<String>{ 'Delivery_Date__c = :deliveryDate' })
36+ .orderBy(new List<String>{ 'Name ASC' })
37+ .build()
38+ .execute(new Map<String, Object>{ 'deliveryDate' => deliveryDate });
39+```
40+
41+No `AccessLevel` argument = dynamic default (correct for almost all sites). Explicit `AccessLevel.SYSTEM_MODE` only for rules 1/2/3/4/6 in `docs/security/mode-selection.md`, with a rule-citing comment on the line above. Never explicit `AccessLevel.USER_MODE`.
42+
43+- **Aggregate queries** (`COUNT(Id) ... GROUP BY`): QueryService supports `.groupBy(...)` — port aggregates through the builder like any other read; results come back as `AggregateResult`.
44+- **Dynamic SOQL with config-driven field names** (demo pattern: field API names read from a CMDT and interpolated into a query string): mechanically portable since QueryService takes string field lists, but the config value is user-influenced input — validate each configured field name against the object's describe (or an explicit allowlist) before building the query. Never interpolate raw CMDT strings into a filter clause.

60+## 4. Class placement & naming
61+
62+| Demo class role | Product location | Naming |
63+| --- | --- | --- |
64+| LWC controller (`@AuraEnabled` entry) | domain package `controllers/` | no prefix, e.g. `DispatchRouteController` |
65+| Reusable business logic | `executables/` | `E_` prefix |
66+| Domain service | `services/` | `S_` prefix |
67+| Batch/schedulable | `batchJobs/` | `B_` / `BA_` |
68+| Queueable | `queueables/` | `Q_` |
69+| Cross-package LWC-serializable shape | `DTOs/<domain>/` | `XxxDTO`, per ADR-0007 (`global`, `{ get; set; }` props, single no-arg ctor) |
70+| **Inner-class `@AuraEnabled` wrappers** (the most common demo DTO shape — plain public fields nested inside a controller) | hoist to top-level files in `DTOs/<domain>/` | same ADR-0007 rules; plain fields without `{ get; set; }` silently null out across the cross-package Aura bridge |
71+| Internal wrapper/builder | `wrappers/` | no prefix, never `@AuraEnabled` param/return |
72+| Test class `FooTest`/`FooControllerTest` | `tests/` subdir (DTO tests alongside the DTO) | `Foo_T` |
73+
74+Demo classes often mix roles (one controller doing query + calculation + DML). Split per role during the port; the map's component table defines the split.
75+
76+**Name collisions**: Apex class names are unique across the whole `ohfy` namespace, not per package. Check every proposed name against all 11 packages before creating it (`grep -rl "class RouteDTO" */force-app --include="*.cls"`); rename with a feature prefix (e.g. `DispatchRouteDTO`) on collision.

117+## 8. Cross-package surface
118+
119+- Sibling-package Apex access: `@namespaceAccessible`.
120+- LWC in a UI package calling Apex: exclusively through that package's `*_UI_Wrappers.cls` facade (`@AuraEnabled` method delegating 1:1 to a `@namespaceAccessible` domain method). Never import domain controllers directly from a tier-4 LWC. Demo `@AuraEnabled(cacheable=true)` methods keep `cacheable=true` on the **wrapper** method (the domain method it delegates to is plain `@namespaceAccessible`).
121+- Custom Apex types crossing an `@AuraEnabled` boundary between packages: `global` DTO per ADR-0007 — **`{ get; set; }` accessors are mandatory** (plain fields silently null out across the Aura bridge).

140+## 11. Platform-sensitive pieces (flag, don't silently port)
141+
142+These behave differently inside a namespaced managed package than in the demo's subscriber org — each needs a flagged design question in the Phase 2 map:
143+
144+- **Visualforce pages** — none exist in the product today; consider rebuilding on LWC (`lightning:map`, LMS) instead of introducing VF.
145+- **External JS libraries / static resources** (map tiles, charting libs) — licensing, CSP Trusted URLs, and static-resource namespacing all change under the package.
146+- **iframe / `postMessage` origins, Lightning Out** — origins differ on subscriber-org domains.
147+- **Hardcoded aggregation limits / thresholds** — consider CMDT-configurable instead of a magic number.

149+## 12. Callouts & secrets
150+
151+Demo code calls external APIs directly (`Http` + hardcoded URL) with API keys stored in CMDT fields or org config. In a managed package:
152+
153+- **Endpoint** → Named Credential (packaged as external credential + named credential metadata), never a hardcoded URL or Remote Site Setting instruction in code.
154+- **Secret** → never in a CMDT field, custom setting, or source. The key lives in the subscriber org's Named Credential / external credential principal; document the admin setup step in the feature's product docs.
155+- Callout classes get `_T` coverage via `HttpCalloutMock`.
156+- Flag any external API dependency (quota, licensing, terms for redistribution) as a design question in the map.
