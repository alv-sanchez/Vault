Lesson 0002 · Safety Stock Epic (BMS-5068)

Why the Epic Builds Everything Tidily

Lesson 1 gave you the runtime chain. This one answers the other half of your question: why is the epic split into the six stories it is, and why does that split feel clean rather than arbitrary? The whole answer rests on one decision made before a line was written.

1. The decision that made it tidy

The demo ticket (BMS-4025) proposed a brand-new object — Safety_Stock_Override__c — with its own scope picklist, effective dates, status lifecycle, and audit fields. Building that would have meant a parallel override system living next to the one already in production.

The production epic threw that away. It found that the repo already shipped the exact machinery — from earlier tickets (BMS-3819/4609/3822):

  • SKU_Override__c — an item+location DOH override with start/end dates and a reason.
  • B_/BA_SKUOverride_ExpirationProcessor — a nightly batch already flipping overrides Active→Expired.
  • S_InventoryThresholds.resolve() — the waterfall that already resolves an effective target DOH.

So the epic's governing rule became: extend the shipped stack; do not rebuild it. Every child story's description literally opens with a “Reuse — do NOT rebuild” list. That's not tidiness as an accident — it's tidiness as the written contract.

The principle, named Tidy here = one new seam per story, each grafted onto exactly one existing component, additively. No parallel systems, no duplicated lifecycle, no second resolver. The demo's net-new object is the “untidy” counterfactual you can point to.

2. One story = one seam

Because the base already existed, each story could be a single clean extension. Read this as “story → the one thing it bolts onto”:

BMS-4217 · the engine — hardens the demo's DOH order-sizing into S_ReplenishmentOrderSizing, flag-gated, with a fallback that leaves unconfigured SKUs untouched. seam: replenishment order sizing (new service, additive to capacity-fill)
BMS-5636 · scope + lifecycle — adds supplier-scope + Scheduled/Manually-Closed states to the existing SKU_Override__c. No new object. seam: SKU_Override__c fields + resolver's supplier tier
BMS-5638 · notifications — adds expiry & approaching-expiry alerts onto the batch that already runs. Doesn't create a job. seam: BA_SKUOverride_ExpirationProcessor + S_SafetyStockNotifier
BMS-5639 · freeze — two fields on Replenishment_Task__c so the resolved target & its source are stamped at generation time. seam: Replenishment_Task__c (audit fields)
BMS-5640 · UI — one LWC over the same data: list, filter, impact preview, early-close. Tier-4, reads the stack below it. seam: safetyStockManager LWC + controller + DTOs
BMS-5641 (+5754) · reporting — a report type over the override history, plus the estimated additional inventory $ value. seam: Safety_Stock_Overrides report type

Notice the shape: 4217 builds the engine, 5636 feeds it richer config, 5639 records what it decided, 5638 unwinds it safely, 5640/5641 let humans see and steer it. Each depends on the base, not on a fragile web of each other — which is exactly why all six could land in one branch without stepping on themselves.

3. Why “tidy” is a real engineering property, not a vibe

  • Additive = no regression. The fallback contract (Lesson 1) means untouched SKUs behave identically. Reuse of the resolver means no second source of truth to drift.
  • One object = one audit trail. Extending SKU_Override__c instead of adding Safety_Stock_Override__c means override history lives in one place — which is why BMS-5641's report could just point at existing fields.
  • Seam isolation = parallelizable, reviewable stories. A reviewer can reason about BMS-5638 (notifications) without loading the UI story into their head.
The honest asterisk Tidy structure didn't make every AC pass. The PR's own notes flag that Override_Reason__c is still not mandatory at the data layer (would break 8 unrelated test classes — deferred to its own ticket), and the LWC never got an independent live smoke test. Tidy architecture ≠ complete delivery. Knowing where a clean design still left gaps is the senior read of this epic.
