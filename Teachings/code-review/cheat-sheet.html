/code-review — Structure at a Glance

Print this one out. Source of truth: CODE-REVIEW.md and .claude/commands/code-review.md at the OHFY-Split repo root.

The pipeline — "Good Finders Verify Output"

PhaseWhat happens
GatherRead the PR/ticket + diff before any code judgment — the diff is judged against what it claims to do.
FindIndependent parallel "angles": line-by-line bug scan, removed-behavior audit, cross-file caller/callee trace, reuse check, simplification check, efficiency check, altitude (right-depth-of-fix) check.
VerifyEach candidate finding gets one adversarial pass whose job is to try to refute it. Returns CONFIRMED / PLAUSIBLE / REFUTED.
OutputFixed section order, severity-labeled, every finding cited file:line.

Severity ladder

LabelMeaning
BLOCKERViolates a repo hard rule, or will cause a runtime error / data loss / security issue / governor-limit exception in prod.
WARNINGLikely problem or bad practice — should be fixed before merge.
SUGGESTIONMinor style/hygiene — optional but recommended.

Rule: one finding, one severity — no "blocker-ish" hedging. If severity is uncertain because of missing context, it's not a low-confidence BLOCKER — it becomes a ❓ Question instead.

Output section order

SectionCatches
🧭 Focus & High-Impact DecisionsWhere scrutiny went deepest, and decisions that are expensive/impossible to reverse later (schema, released API surface, cross-package dependencies).
🐛 Bugs & Runtime ErrorsWill/likely will crash: null deref, off-by-one, SOQL/DML in a loop, race conditions.
🔇 Silent Failures & Swallowed ErrorsAsync work, empty catches, unchecked partial-DML results, missing Finalizers.
🔀 Conditional Logic & Dead BranchesEffectively-constant conditions, silent guard-clause skips, unreachable/identical branches.
🧹 Dead CodeCommented-out blocks, unreachable code, unused vars/imports.
🔍 Debug StatementsSystem.debug, console.log, .only(, .skip( left in.
🏷️ Naming Convention ViolationsLabel/API-name mismatches, casing rules.
❓ Questions for the AuthorAnything whose severity depends on business/data context the reviewer doesn't have — asked, not guessed.
👏 KudosSpecific, line-cited good work. 1–3 items, only if genuinely earned.
✅ SummaryIs this safe to merge — blockers vs. suggestions, patterns worth noting.

Why the shape, not just what it is — F.A.C.T.

LetterRuleFights
Focus firstHigh-impact/irreversible decisions get their own section, read before nits.Burying the one thing that matters under 40 style nits.
Ask, don't assumeUncertain findings become questions, not confident guesses.False certainty / wrong-but-confident blockers that burn trust.
Cite file:lineEvery claim points at real, checkable code.Unverifiable authority — claims taken on faith or dismissed outright.
Tier by severityOne finding, one severity, no hedging.Alert fatigue — if everything's urgent, nothing is.
