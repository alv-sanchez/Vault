Gather Diff + Ticket Context
Orchestrator collects the review scope and Jira context

Runs git diff @{upstream}...HEAD (falls back to main or HEAD~1). If committed diff is empty, includes uncommitted working tree changes. Extracts ticket key from branch name and fetches Jira summary + acceptance criteria if an Atlassian MCP is available. Also checks for a CODE-REVIEW.md at repo root for repo-specific rules.

Find Candidates

Correctness Angles
Sonnet

A: Line-by-Line Scan

Reads every hunk + enclosing function. Hunts: wrong conditions, off-by-one, null deref, missing await, error swallowed, copy-paste bugs.

Sonnet

B: Removed-Behavior Auditor

For every deleted/replaced line, names the invariant it enforced. Searches new code for where that invariant is re-established.

Sonnet

C: Cross-File Tracer

Greps for callers of each changed function. Checks if the change breaks call sites, return shapes, preconditions, or ordering.

Cleanup Angles
Sonnet

Reuse

Flags new code that re-implements something the codebase already has. Names the existing helper.

Sonnet

Simplification

Redundant state, copy-paste variation, deep nesting, dead code. Names the simpler form.

Sonnet

Efficiency

Redundant I/O, sequential independent ops, blocking on startup, closures retaining large scopes.

Sonnet

Altitude

Is the fix at the right depth? Fragile bandaids on shared infra suggest the underlying mechanism should be generalized.

▼
2
Adversarial Verification
Each candidate tested by an agent instructed to REFUTE it

After deduplication (same line/mechanism → keep the best failure scenario), each surviving candidate faces a verifier given the diff, relevant files, and the candidate — told to try to prove it wrong.

CONFIRMED — names inputs + wrong output, quotes the line
PLAUSIBLE — mechanism real, trigger uncertain (timing/env/config)
REFUTED — factually wrong or guarded elsewhere, quotes proof

At low/medium effort, PLAUSIBLE findings are dropped unless nothing else survives. At high/max, they're kept.

Built-in Plugin vs. Custom Override

Your ~/.claude/commands/code-review.md overrides the built-in plugin when both are present. Here's how they differ.

Built-in Plugin

  • PR-only (requires gh + open PR)
  • 5 Sonnet review agents
  • Haiku for triage, summary, scoring
  • Confidence scoring (0-100 per issue)
  • Hard threshold: score ≥ 80
  • Checks CLAUDE.md compliance
  • Checks prior PR comments on same files
  • Checks inline code comments
  • Skips drafts, closed, trivial PRs
  • Output: PR comment only
  • No effort scaling — one mode
  • No adversarial verification step

Custom Override

  • Works locally — no PR required
  • 7 finder angles (3 correctness + 4 cleanup)
  • All subagents pinned to Sonnet
  • Adversarial verification (try to REFUTE)
  • CONFIRMED / PLAUSIBLE / REFUTED verdicts
  • Effort scaling: low / medium / high / max
  • Jira ticket context via MCP
  • Checks CODE-REVIEW.md for repo rules
  • Falls back to uncommitted working tree
  • 3 output modes: terminal / --comment / --fix
  • Cross-file call-site tracing (Angle C)
  • "Altitude" check — is fix at the right depth?
