Presentation Guide

Claude Code Review — Takeaway

Walk-through order, talking points, and key callouts for presenting the hybrid code review proposal to the team.

Presentation Order — 10 Sections

1 The Problem — 60% of our review surface ships unchecked. Set the stakes. 2 min
2 What We Have Today — 6 CI jobs, 4 manual AI skills, /audit-pull-request. Acknowledge the foundation. 2 min
3 Where /audit-pull-request Falls Short — 40% coverage, diff-only, no conventions. Real code scenarios. 4 min
4 What /code-review Adds — 88% coverage, reads full repo + CLAUDE.md, inline comments, cross-file analysis. 3 min
5 The Hybrid Approach — Triple Guard: local AI + CI/CD safety net + human review. The core proposal. 3 min
6 Time Savings — 30-50 min down to 10-15 min per PR. Human reviewer focuses on architecture, not checklists. 2 min
7 Cost & Controls — $2-4 per CI review (on-demand), $0 for local. --max-turns, trigger options, cancel mid-run. 3 min
8 When to Skip / When to Always Run — Metadata-only = skip. Apex/LWC/cross-package = always. 2 min
9 The Ask — One admin action (API key), $200 plan upgrade, pilot on 10-15 real PRs this week. 2 min
10 What This Doesn't Replace — Human judgment, CI pipeline, /polish. AI is additive, not a replacement. 1 min

1 The Problem ~2 min

Open with the gap. Don't start with the solution — start with what's at risk.

Key stat: 60% of our review surface — security, project conventions, cross-file regressions, test coverage — has no automated enforcement today. It's checked only if the human reviewer remembers, has bandwidth, and is familiar with that part of the codebase.

Ground it in specifics they'll recognize:

  • QueryService/DmlService mandate (BMS-3965) — enforced by memory, not automation
  • Logger-in-catch (BMS-4298) — a System.debug() in a catch block means the error never reaches Datadog
  • DTO { get; set; } (ADR-0007) — passes unit tests, deserializes as all-null in customer org installs
  • SYSTEM_MODE without rule citation — privilege escalation with no paper trail
  • Review depth varies by workload — crunch weeks = shallow reviews = escaped bugs
Don't say: "Our reviews are bad." Do say: "We have solid CI and smart engineers, but the mechanical parts of review don't scale with workload. The conventions we've documented aren't automatically enforced."

2 What We Have Today ~2 min

Acknowledge the existing quality gates. This isn't starting from zero — we already have strong CI. The gap is in the review layer, not the build layer.

  • Pre-commit hooks — Husky + lint-staged: Prettier, ESLint, Jest on changed LWC
  • CI pipeline — 6 jobs: Prettier verify, Jest, hex-lint, sfdx-git-delta deploy, Apex tests (smart selection), Playwright E2E
  • /audit-pull-request (PR #243) — 126-line custom skill, 6 dimensions, posts structured PR comment
  • /code-review — Claude Code built-in, inline PR comments with severity (manual trigger)
  • /set-risk, /polish — risk assessment and pre-refinement validation
Call out: All 4 AI skills are manually triggered. None run automatically. Coverage depends on whether an engineer remembers to run them.

3 Where /audit-pull-request Falls Short ~4 min

This is the core of the argument. Show the 40% vs 88% coverage meters, then walk through 2-3 real code scenarios. Don't show all 6 — pick the ones that resonate with recent bugs or near-misses.

Coverage: 40%. The audit skill reads the PR diff and nothing else. It doesn't know CLAUDE.md exists. It can't open a related file. It can't tell you a catch block is missing Logger because it doesn't know Logger is required.

Pick 2-3 scenarios to walk through live (from the Audit-vs-CodeReview.html file). Recommended:

  • Scenario 1: Raw DML bypassing QueryService — Database.insert(records, SYSTEM_MODE) without AccessLevelResolver. Audit sees nothing wrong. Code-review reads CLAUDE.md, flags BMS-3965 + missing SYSTEM_MODE citation. Impact: security regression.
  • Scenario 2: DTO missing { get; set; } — The managed-package null bug. Passes every unit test. Breaks silently in customer orgs. Audit doesn't know ADR-0007 exists. Impact: invisible runtime failure.
  • Scenario 3: Class rename breaks ServiceLocator — CMDT still points to old class name. No compile-time check. Audit only reads the diff, can't see CMDT records. Code-review opens them. Impact: TypeException in production.
Anticipated question: "Can't we just improve the audit skill?" Yes, but it's structurally diff-only. You can add more checks to the diff, but you can't make it read CLAUDE.md, open related files, or do cross-file analysis. That's a different architecture — which is what /code-review already provides.

4 What /code-review Adds ~3 min

Now show the 88% side. Emphasize what's fundamentally different — not "more checks" but "reads the full repo."

Coverage: 88%. /code-review is a multi-turn agent that reads the diff, CLAUDE.md, REVIEW.md, then opens related files — callers, services, tests, CMDT records — to build full context before posting findings.

Key differences to emphasize:

  • Reads CLAUDE.md — knows our conventions: QueryService, DmlService, Logger-in-catch, DTO pattern, SYSTEM_MODE rules
  • Reads REVIEW.md — shared rulebook that governs severity, volume caps, skip rules, Salesforce-specific "always check" list
  • Cross-file analysis — opens callers, services, test files, metadata beyond the diff. Catches regressions invisible in changed lines alone
  • Inline comments — findings posted on the exact PR line, not a wall-of-text comment. Reviewer sees what was flagged and where.
  • Security — SOQL injection, XSS, CRUD/FLS, exposed @AuraEnabled, SYSTEM_MODE citations. Entire category missing from audit.

5 The Hybrid Approach — Triple Guard ~3 min

This is the proposal. Walk through the Triple Guard flow. Emphasize: three independent layers, one shared rulebook.

Guard 1 — Local AI: Engineer runs /code-review --comment before pushing. Pre-push self-review. Same REVIEW.md rules. $0 (included in Max subscription). No turn limit.

Guard 2 — CI/CD Safety Net: GitHub Action fires on-demand via @claude comment (or auto on ready_for_review). Posts inline comments. ~$2-4 per run. Cancellable mid-run.

Guard 3 — Human Review: Teammate reviews the PR. Mechanical checks already done. Focuses on architecture, domain logic, UX. Faster, higher-quality review.

Key callout: Both AI layers follow the same REVIEW.md rulebook. Same rules, same severity definitions, same skip list. No drift between what different engineers or the CI checks for.

6 Time Savings ~2 min

Show the time comparison cards. This is the "what's in it for me" for every engineer in the room.

Without hybrid: 30-50 min per PR (convention checks 10-15 min + bug/security scanning 10-20 min + architecture review 10-15 min).

With hybrid: 10-15 min per PR. Convention checks and bug scanning automated. Human time focused on architecture + reviewing AI findings.

Frame it as: "This doesn't take review away from engineers. It takes the mechanical checklist off their plate so they can focus on the parts that actually require human judgment."

7 Cost & Controls ~3 min

Address the "$20 per PR" fear head-on. Explain how trigger configuration controls cost, not the tool itself.

The "$20/PR" myth: That happens when you trigger on every synchronize event — every commit fires a full review. 5 pushes = 5 reviews = $10-20+. With comment-only trigger (@claude), you pay ~$2-4 only when you explicitly ask for it.
  • Local /code-review — $0 per review (Max subscription). No turn limit. Unlimited runs.
  • CI/CD review — ~$2-4 per run (Sonnet 4.6). On-demand via @claude comment. Cancellable from Actions tab.
  • --max-turns 10 — recommended balance. Sequential depth, not parallel agents. Each turn reads one file. Cost compounds because each turn re-sends all prior context.
  • Monthly estimate: ~40 PRs/month × ~$3 avg = ~$120/mo for CI layer. Plus existing Max subscriptions for local.

Trigger options to mention (from the Hybrid Proposal):

  • @claude comment (recommended) — on-demand, controlled by the engineer
  • GitHub label — add claude-review label to the PR
  • PR template checkbox — opt-in at PR creation time
  • Draft → Ready for Review — auto once when PR leaves draft
  • Avoid: on every push (synchronize) — this is the cost blowout trigger

8 When to Skip / When to Always Run ~2 min

Show you've thought about when NOT to spend money. This builds trust that the proposal is cost-conscious.

Skip AI Review:
• Metadata-only PRs (field-meta.xml, perms, layouts)
• Version bumps only
• Documentation-only (.md files)
• Org-metadata snapshot sync
• Namespace removal (ohfy__)
• File reorganization (folder moves)
• Trivial one-liners
Always Run AI Review:
• Any Apex change (classes, triggers)
• Any LWC change (JS, HTML, CSS)
• Cross-package changes (DTOs, ServiceLocator)
• Trigger service modifications
• Security-sensitive code (@AuraEnabled, SYSTEM_MODE)
The discretion principle: The PR creator decides whether to trigger a review. The @claude comment trigger and GitHub label both put this in the engineer's hands — not automated for every push, not skipped by default.

9 The Ask ~2 min

Be specific. One admin action, everything else is ready.

What we need:
  • One admin action: Add ANTHROPIC_API_KEY to GitHub repo secrets (Settings → Secrets → Actions). This is the only step that requires admin access. I have write access for everything else.
  • Upgrade proposal: Move from Max $100 to $200/seat/month — 5x usage for local /code-review runs. $0 per review, no turn limit, no throttling during crunch weeks. Less than the cost of one escaped DTO bug hitting a customer org.
  • Pilot plan: Run on 10-15 real PRs this week. Check API usage dashboard for actual costs. Assess signal-to-noise. Tune REVIEW.md skip rules based on findings. If quality isn't there, iterate before committing.
Confidence boost: Coverage goes from ~40% (human-only, inconsistent) to ~92% (AI + human, uniform). Review time drops from 30-50 min to 10-15 min per PR. Conventions enforced on every PR, not just when someone remembers.

10 What This Doesn't Replace ~1 min

Close by acknowledging limits. This builds credibility and prevents the "are you trying to replace code review?" pushback.

  • Human judgment — Architecture decisions, UX feedback, domain logic, "should we even build this?" Still needs a human.
  • CI pipeline — Compile errors, test failures, Prettier, deploy validation. All still runs as-is. AI review is additive.
  • Pre-refinement — /polish and ticket validation are a different phase entirely. Hybrid review is merge-time, not planning-time.
  • /audit-pull-request — Keep it for quick Salesforce-specific sanity checks. It's complementary, not replaced.
Final line: "This isn't AI replacing reviewers. It's AI doing the mechanical checklist so reviewers can focus on what actually requires their expertise."
