The rule this encodes. Build custom only where the data is runtime-computed or runtime-filtered. Everything backed by stored records — order history, pricing, the supervisor aggregate — stays native or reuses an existing component, because rebuilding it would duplicate a first-class Salesforce surface.

Search / filter / pagination on the above accountOrderVisibility Custom These computed panels aren't list views, so they can't inherit native list-view filtering — they carry their own search, filter, and paging.

Net — the custom surface is the accountOrderVisibility LWC on the Account record page (delivery banner · promotions eligible + not-eligible · top products · inventory, all searchable/paginated). Everything backed by stored records stays native: order history (related list), supervisor aggregate (report), pricing (accountPricingPanel), order creation (order modal).
