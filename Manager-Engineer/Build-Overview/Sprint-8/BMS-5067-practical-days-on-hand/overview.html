📊 BMS-5067 — Practical Days on Hand

Inventory Management · phase walk · epic In Progress · org ohfy-val-5067

🧠 In one line: Show each item's actual days-on-hand vs the leadership-set target, right where planners work — so over/understock is obvious at a glance, without spreadsheets.

👤 The user

Gulf inventory analysts & supply-chain leadership. Two grains, two audiences:

  • Purchasing works at the warehouse grain — "are we over/under target across McCalla?"
  • Warehouse ops works at the location grain — "is this pick face short vs its target?"

💥 Business impact

Today: planners judge inventory health with ad-hoc averages and tribal knowledge. There's a leadership-set "practical" DOH target, but nothing compares live stock against it in the system — so the target lives in spreadsheets.

The cost of that: excess inventory ties up space in tighter warehouses (Huntsville, Montgomery) while high-velocity SKUs stock out in Milton/Mobile — because no one sees the variance until it bites.

The win: the target-vs-actual gap becomes a system field + report column — an overstock/understock signal analysts can filter and act on, at the grain they own.

🛠️ Proposed solution

Reuse-first, declarative — no new objects, no code. The benchmark storage + DOH/DOI calculation already shipped; this surfaces the variance on top of it:

Variance fields

On Inventory__c: days (Current_DOI − Effective_Target_DOH), %, and a status (Above / At / Below Target · No Benchmark Set · No Velocity Data). Formula fields — always in sync, nothing to run.

Report

Those columns added to the shipped "Days of Inventory" report type. Warehouse view via grouping; location view by filtering. No new dashboard.

Docs

Warehouse-vs-location behavior documented for the team + Gulf.

Deliberately out of scope (deferred): provisional new-item benchmarks, seasonal/capacity engine, CSV import, supplier-tier resolution, a bespoke planning dashboard.
