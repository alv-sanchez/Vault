Transfer Dock Optimization

Capacity-aware dock booking for inter-warehouse transfers — a delta that extends the already-shipped dock scheduler, not a replacement. Blocks overbooking and suggests alternatives.

Status Review Assignee Alvaro Sanchez Epic Dock Mgmt & Inbound Scheduling Labels build · gulf · polished · walk

01 Why this exists

Gulf runs transfers across 5 warehouses with non-uniform dock/crane capacity and legacy supplier-dedicated lanes. Overbooking one dock window doesn't stay local — it cascades.

The failure mode

A dock window gets booked past what the dock can physically absorb. There's no capacity gate today, so the conflict only surfaces on the loading floor.

Overbooked window→ Delayed route load→ Missed delivery window

02·7 What the dashboard actually pulls — every SOQL behind the board

All reads/writes route through QueryService.newBuilder() / DmlService (USER_MODE by default via AccessLevelResolver). Below is the literal SOQL each builder emits. The two yellow cards are net-new for BMS-4490 — the capacity guard and the alternative-slot suggester.

Active docks for the warehouse · getDockSchedule()READ
SELECT Id, Name, Location_Code__c, Dock_Capacity_Minutes__c, Dock_Notes__c
FROM   Location__c
WHERE  Parent_Location__c = :warehouseId
  AND  Is_Dock__c   = TRUE
  AND  Is_Active__c = TRUE
ORDER BY Name ASC
Populates the columns on the board. Empty result → the "No docks found" message you hit — the selected warehouse has no active Is_Dock__c children.
Booked appointments for the selected day · getDockSchedule()READ
SELECT Id, Name, Origin_Dock__c, Origin_Dock_Time__c,
       Destination_Dock__c, Destination_Dock_Time__c,
       Delivery__c,       Delivery__r.Name,       Delivery__r.Status__c,
       Purchase_Order__c, Purchase_Order__r.Name, Purchase_Order__r.Status__c,
       Transfer_Group__c, Transfer_Group__r.Name, Transfer_Group__r.Status__c,
       Shipment_Time_Minutes__c
FROM   Shipment__c
WHERE  (Origin_Dock__c IN :dockIds OR Destination_Dock__c IN :dockIds)
  AND  ((Origin_Dock_Time__c      >= :startOfDay AND Origin_Dock_Time__c      < :endOfDay)
    OR  (Destination_Dock_Time__c >= :startOfDay AND Destination_Dock_Time__c < :endOfDay))
One tile per side. Tile length = Shipment_Time_Minutes__c (default 60); start = the dock-time field. Cancelled/Complete parents are dropped in Apex, not SOQL. Pass selectedDate = null to skip the day filter (all active appointments).
Unassigned records for the day · getUnassignedRecords() — Transfer Group variantREAD
SELECT Id, Name, Status__c, Origin_Location__c, New_Location__c,
       (SELECT Origin_Dock__c, Origin_Dock_Time__c,
               Destination_Dock__c, Destination_Dock_Time__c
        FROM Shipments__r)
FROM   Transfer_Group__c
WHERE  (Origin_Location__c = :warehouseId OR New_Location__c = :warehouseId)
  AND  Transfer_Date__c = :selectedDate
  AND  Status__c != 'Complete'
ORDER BY Name ASC
Feeds the side panel — a record is "unassigned" when its child Shipment lacks the relevant dock + dock-time. Delivery (filter Delivery_Date__c, needs Origin side) and Purchase Order (filter Fulfillment_Location__c + Expected_Delivery_Date__c, needs Destination side, + BOL status) variants are analogous.
Conflict scan on the target dock · validateNoConflict() — the conflict authorityGUARD
SELECT Id, Origin_Dock__c, Origin_Dock_Time__c,
       Destination_Dock__c, Destination_Dock_Time__c, Shipment_Time_Minutes__c,
       Delivery__c, Delivery__r.Name, Delivery__r.Status__c,
       Purchase_Order__c, Purchase_Order__r.Name, Purchase_Order__r.Status__c,
       Transfer_Group__c, Transfer_Group__r.Name, Transfer_Group__r.Status__c
FROM   Shipment__c
WHERE  Origin_Dock__c = :dockId OR Destination_Dock__c = :dockId
Runs on every assignDock / updateDockAppointment. Interval-overlap is computed in Apex: existing window [time, time + mins] vs. the proposal window. Excludes the parent being edited. Fires for all parent types.
Target-dock capacity lookup · enforceTransferDockCapacity() — BMS-4490NEW · GUARD
SELECT Id, Name, Dock_Capacity_Minutes__c, Parent_Location__c
FROM   Location__c
WHERE  Id = :dockId
LIMIT  1
Transfer-Group bookings only. If Shipment_Time_Minutes__c > Dock_Capacity_Minutes__c the booking is blocked (slot-fit, not a daily budget). No-op when capacity is null or the window fits.
Alternative-dock candidates + their appointments · buildAlternativeDockSuggestions() — BMS-4490NEW · SUGGEST
-- candidates: other active docks with a big-enough slot
SELECT Id, Name, Dock_Capacity_Minutes__c
FROM   Location__c
WHERE  Parent_Location__c = :warehouseId
  AND  Is_Dock__c = TRUE  AND  Is_Active__c = TRUE
  AND  Id != :excludeDockId
  AND  Dock_Capacity_Minutes__c >= :durationMins
ORDER BY Dock_Capacity_Minutes__c ASC, Name ASC

-- availability: appointments already on those candidate docks
SELECT Id, Origin_Dock__c, Origin_Dock_Time__c,
       Destination_Dock__c, Destination_Dock_Time__c, Shipment_Time_Minutes__c,
       Delivery__c, Purchase_Order__c, Transfer_Group__c
FROM   Shipment__c
WHERE  Origin_Dock__c IN :candidateIds OR Destination_Dock__c IN :candidateIds
Only reached when the capacity guard blocks. Docks open at the requested window surface first (with the open time); booked-but-big-enough docks are flagged "booked at this time". Capped at 3 suggestions.

03 The behavior being built (acceptance criteria)

Given

A Transfer Group needs a destination dock appointment, and that dock's remaining capacity — existing Shipment__c appointments vs. Dock_Capacity_Minutes__c — cannot absorb the requested window.

When

A warehouse manager attempts to book the slot.

Then
⛔ Booking blocked — capacity / conflict explanation shown

…and at least one alternative that respects existing appointments is offered:

↪ alternative dock 🕐 alternative time slot

04 Two implementation paths — pick ONE at implementation time

SPEC A

Off-Platform

New dock-optimization module in product-portal-api (Node / Nest)

Pro

  • Unlimited compute — no governor limits on slot-search across 5 warehouses
  • React calendar/board UI freedom beyond LWC
  • Iterate outside managed-package release cadence

Con

  • Dock truth lives in Shipment__c — suggestions must round-trip validateNoConflict or risk double-booking on sync latency
  • SF write-back auth + idempotency are net-new (no write path exists)
  • No CDK stack / deploy workflow yet; WMS entitlement seeded inactive
  • Dual-deploy burden for 100%-on-platform data & UI
  • Needs incremental watermark (appointments = near-real-time; no CDC/Platform Events)
  • JWT-bearer flow for unattended worker
    • SPEC B

    Salesforce-Native

    Extend E_DockScheduler in OHFY-Split (Apex + dockDashboard)

    Pro

    • Extends the shipped scheduler in place — single source of truth, zero sync latency
    • dockDashboard UI, trigger framework, permission model already exist
    • No new infrastructure or auth surface

    Con

    • Governor limits constrain heavy slot-search (SOQL / CPU ceilings)
    • New Location__c fields/picklists = frozen managed-package API, visible to all subscribers
    • Managed-package release cadence; browser-vs-SF timezone watch-item inherited
  • Reads QueryService.newBuilder(); writes DmlService + AccessLevelResolver
  • Cross-package shapes via WMS_UI_Wrappers / ADR-0007 DTOs; OpenSpec proposal expected
    • Weight of evidence leans Spec B: the data (Shipment__c), the conflict authority (validateNoConflict), and the UI (dockDashboard) are already on-platform. Spec A's chief liability is sync latency against a near-real-time source of truth with a net-new write-back path. Governor limits are the real Spec B risk to validate against 5-warehouse slot-search volume.

    05 Open questions — must resolve before / during build

    1

    Is Dock_Capacity_Minutes__c enough, or do we need a per-dock throughput field?

    Per-warehouse crane/equipment throughput differs (McCalla vs. Montgomery). A new field on Location__c means a frozen managed-package surface on a massively shared object.

    Is the supervisor conflict-override in scope?

    The DOCK-SCHEDULING-PLAN's Bypass_Dock_Conflict__c permission was never implemented — do not assume it exists. Decide whether this build introduces it.

    3

    Model legacy supplier-lane dedication as data, or leave to operator judgment?

    Per-dock allowed-sources data vs. trusting the warehouse manager. Affects whether the slot suggester filters by supplier lane.

    06 Verified constraints — don't trip these

    ✗ Deprecated dock fields

    Per-object dock fields (Transfer_Group__c.Origin_Dock__c, Delivery__c.Dock__c, PO dock fields) are no longer read/written. Resurrecting them forks the source of truth.

    ✗ Bypass_Dock_Conflict__c

    Never implemented. Do not assume the supervisor-override permission exists (see open question #2).

    ✗ "Dock" is not a Type__c

    Docks are Location__c.Is_Dock__c (mutually exclusive with Is_Truck__c). Don't filter on a Type value.
