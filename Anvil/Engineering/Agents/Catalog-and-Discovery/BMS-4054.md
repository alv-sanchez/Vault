## Polish (build-fleet run) — 2026-06-12

**Residual scope** (post-Validation-Run-0; grid + pagination + shared catalog/search card path already live on main — do NOT rebuild):

1. **Promotions-first default sort** — on initial catalog load and whenever the "default" sort is selected, items with active promotions (`item.hasPromotions`, already loaded client-side via `itemToPromotionsMap` before `processItems`) render before non-promoted items; within each group in-cart items come first; otherwise order is stable. Both sort dropdowns (desktop header ecomShop.html:~110, mobile drawer ~1199) relabel "default" to "Promotions First".
2. **"Cart Items First" preserved as an explicit option** — new sort value `cart` keeps today's default behavior selectable (managed-package UX continuity).
3. **Image-error fallback fixed** — `ecomProductCard.handleImageError` currently sets `src=""` (broken-image glyph / potential error loop). It must fall back to the `ecomNoProductImage` / `defaultKeggedProductImage` static resources (same fallbacks ecomShop.processItems uses for null `Logo_URL__c`), with a one-shot guard.
4. **Image sizing consistency + perf** — card images lazy-load (`loading="lazy"`, 200-SKU pages / 3s SLA) and render inside the existing fixed-height `object-contain` frame with padding so oversized images don't touch card edges; identical frame across all cards.
5. **Card-component adoption (BMS-4053)** — catalog + search results render exclusively through `c-ecom-product-card`. Already satisfied by the stacked base branch (4053 replaced the inline markup in ecomShop.html); this ticket verifies and keeps it, no rebuild.
6. **Tests** — Jest coverage for the new sort branches + image fallback; Playwright spec asserting promotions-first default ordering on the storefront.

**Excluded as already shipped** (evidence in Validation Run 0): responsive grid (ecomShop.html:1033), page-list pagination 25/50/100/200 (ecomShop.js:105-127, 2012-2033), search-results reuse (same `paginatedItems` render path), card chrome (now in ecomProductCard via 4053).
