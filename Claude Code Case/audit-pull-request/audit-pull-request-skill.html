Audit Criteria

6 dimensions

🐛 Bugs & Runtime Errors

  • SOQL queries inside loops (governor limit)
  • DML statements inside loops (governor limit)
  • Null dereference without prior null check
  • Divide by zero (literal or unchecked)
  • Index out of bounds without size check
  • Map.put() with non-unique keys (silent overwrite)
  • Missing break in switch fall-through
  • Race conditions in LWC reactive properties
  • Sync/async mismatch in LWC/Aura
  • Uninitialized variable reads

🔇 Silent Failures & Swallowed Errors

  • Async Apex (Queueable/Batch/Future) without try/catch on failable work
  • Empty or swallowing catch blocks
  • Over-broad catch(Exception) that continues
  • Partial-success DML results never inspected
  • Queueable without Finalizer on failable work
  • LWC promises with no .catch() or try/catch
  • Failures logged but never surfaced to user

🔀 Conditional Logic & Dead Branches

  • Effectively constant conditions (hardcoded flag)
  • Conditions that almost always take one route
  • Silent conditional skips on common cases
  • Identical if/else branches
  • Unreachable else/case/default paths
  • Redundant nested conditions

🧹 Dead Code

  • Commented-out blocks (more than one line)
  • Unreachable code after return/throw
  • Unused variables, parameters, or imports

🔍 Debug Statements

  • System.debug() in Apex production code
  • console.log() in LWC/JavaScript
  • console.warn() / console.error() left in

🏷 Naming Conventions

  • Apex: PascalCase classes, camelCase methods
  • Constants: UPPER_SNAKE_CASE
  • LWC: camelCase folders, methods, functions
  • Metadata: label-to-API-name matching

⚠

Severity Levels

[BLOCKER] Runtime error, data loss, or governor limit exception in prod
[WARNING] Likely problem or bad practice — fix before merge
[SUGGESTION] Minor style or hygiene — fix optional but recommended
📄

Output Format

## PR Audit Report
**PR:** <title and URL>
**Files changed:** <count> | **Lines added:** <+n> | **Lines removed:** <-n>

---

### 🐛 Bugs & Runtime Errors
<file>:<line> — <description and why it causes a problem>

### 🔇 Silent Failures & Swallowed Errors
<file>:<line> — <what can fail, why hidden, how to handle>

### 🔀 Conditional Logic & Dead Branches
<file>:<line> — <which branch is dead/always-taken, and why>

### 🧹 Dead Code
<file>:<line> — <description>

### 🔍 Debug Statements
<file>:<line> — `<the statement>` — remove before merge

### 🏷 Naming Convention Violations
<file> — <what was found> → <what it should be>

### ✅ Summary
2–3 sentence assessment: safe to merge? blockers vs suggestions?
Sections with no findings are omitted entirely.
