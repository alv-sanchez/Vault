The Problem

Fragmented promotion resolution across consumers

Before this PR, every consumer that needed a promotion-adjusted price (desktop invoice, mobile invoice, credits, sell-from-truck, e-commerce, integrations) had to independently resolve promotions on top of the FLP base. This meant:

  • Duplicate logic — each consumer reimplements eligibility, scope matching, threshold gating, and best-for-customer selection
  • Cart-unaware pricing — QD (Quantity Discount) tiers must evaluate against the summed quantity of all in-scope cart lines, not per-line. Without a cart-aware resolver, the same item split across lines would mis-tier
  • No single auditable path — different consumers could produce different prices for the same cart, with no way to trace which promotion won or why
The Solution

S_PriceResolver.resolve(CartResolutionRequest) — one path, every consumer

A single global Apex service that takes the entire cart (account, location, date, all lines) and returns one LineResult per line with the FLP base + winning promotion discount layered on top. Every consumer routes through this one method.

  • Layers on FLP — delegates to S_FrontLinePricing.resolve() for the base price, never re-queries Front_Line_Price__c directly
  • Cart-aware QD tiering — sums quantities across all in-scope cart lines before selecting the tier threshold
  • Bulk-safe — flat SOQL count regardless of cart size (1 line vs 200 lines = same query count)
  • Time-travel — asOfDate anchors every date comparison (live = today, credits = original invoice date, integrations = event timestamp)
