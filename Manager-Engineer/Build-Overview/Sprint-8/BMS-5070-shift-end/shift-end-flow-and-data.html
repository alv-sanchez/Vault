Shift-End — the two breakage streams & what it actually reads

BMS-5070 · there are TWO independent breakage-capture flows. Shift-End reconciles only the Pick Path one.

Two places breakage is recorded (different objects, different flows)

🧾 Pick Path — warehouse picking

  • UI: pickPathStop.js → E_PickPathFulfillment
  • Records to: Pick_Event__c
  • Fields: Reason__c='DAMAGED', Breakage_Quantity__c, on the picked bin Location__c
  • Who/when: picker, during the shift, per stop
  • ✅ Shift-End READS this

🚚 Add-to-Truck — delivery / load-out

  • UI: addToTruck.js (OHFY-OMS-UI) → AddToTruckController
  • Records to: Invoice_Item__c.Unsold_Reason__c + Credit__c + Inventory_Adjustment__c
  • Values: Breakage - Retail / Breakage - Driver / Breakage - Warehouse
  • Who/when: driver / delivery, at load-out or the stop
  • ❌ Shift-End does NOT read this
✅ Correction: earlier I said "add-to-truck records no breakage" — that was wrong. Add-to-Truck does record breakage, via unsold Breakage-Retail/Driver/Warehouse reason codes (credits + inventory adjustments). It's simply a separate stream on a different object than the one Shift-End reads.
⚠️ Gap to flag: Shift-End's breakage = Pick Path pick events only. Delivery breakage captured at Add-to-Truck (Breakage-Driver/Retail) is not pulled into the shift close-out today. If "shift shrinkage" should include delivery breakage, that's a product decision, not currently built.

The two breakage flows are parallel, not sequential — Pick Path breakage happens in the warehouse during picking; Add-to-Truck breakage happens on the delivery side. Shift-End only reconciles the warehouse (Pick Path) one.

How Shift-End is scoped to Pick Path (no FK — attribute match)

S_BreakageReview.getDamagedEvents(warehouseId, shiftDate) pulls the same Pick_Event__c rows the Pick Path wrote, matched on 3 things:
  • Reason: Reason__c = 'DAMAGED'
  • Warehouse: the picked bin's Location__r.Warehouse__c (formula: bin → warehouse Name) = :warehouseName
  • Date: Timestamp__c within the shift date's GMT day window
No lookup/FK from Pick_Event__c to the checklist — it's an attribute match. Sign-off writes only the review fields (Breakage_Reviewed__c, reviewer, timestamp); it never edits Breakage_Quantity__c/Reason__c.
