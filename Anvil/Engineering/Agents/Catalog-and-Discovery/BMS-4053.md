## Decisions

1. **Reuse the existing fieldset framework instead of inventing one.** Emily authored `E_FieldsetCustomizationMDT` + `U_FieldUtility` (OHFY-Utilities, 2023) — exactly the "field set or configurable data element" she described in comment 40736. New purposes/field sets/CMDT records plug into it; no new framework code beyond the thin ecom controller.
2. **`Fieldset_Customization__mdt.Object_Name__c` unique constraint loosened (true → false).** The framework's own resolver queries by (Object_Name__c AND Fieldset_Purpose__c) — a per-object unique constraint makes the purpose picklist unusable (deploy failed with "duplicate value ... duplicates value on Default Item Fieldset"). The (object, purpose) pair is the logical key; documented in the field description. Latent data-model bug, not a behavior change for existing single-record-per-object orgs.
3. **Config-only Apex; values ride the existing catalog query.** `getProductDisplayFields` returns [{apiName,label,type}]; userDataService appends those API names to its `getFilteredRecords` Item__c query. No second value-fetch round trip, and FLS is enforced twice (accessible-field filter server-side + the query itself).
4. **Reference-type fields excluded from display config** — rendering a raw record Id is never the desired retailer-facing display; non-reference field types formatted client-side (boolean→Yes/No, currency→$x.xx, percent→x%).
5. **Purpose values restricted server-side** to the two ecom purposes so community users cannot enumerate arbitrary field sets (e.g. internal `Item_Default`).
6. **UPC ships as the default content of both field sets** — closes Alvaro's open UPC question with a reversible default (admin removes the field from the field set to hide it). FLS pre-existing (profile line 5460).
7. **Quantity-input validation moved INTO the card** (reset + warning toast) because the parent can no longer reach across the shadow boundary to reset the input; `quantitychange` only ever fires with a valid int ≥ 1.
8. **Brand accent NOT built** — parked to `_shared/blockers.md`: no brand color/logo field exists on Item_Type__c; requires a product decision (new packaged field vs derived accent vs drop).
9. **PRC waterfall treated as satisfied by the merged S_FrontLinePricing cascade** (BMS-3876 is Done in Jira); deeper volume/promo layering is out of card scope.
