Glossary (so the rest reads clean)

Billback = the tab

One per supplier. Holds who owes, the status (Accrued → Invoiced → Collected), and the rolled-up total.

Billback Line = an item on the tab

One per source charge. Holds the amount, the charge type, the coverage %, and the recoverable. Sum of lines = the tab total.

① Cross-state transfers — the new multi-supplier split

Freight is a single number typed in (from the carrier invoice) — the system doesn't compute it, so it can't break it into components. What it can now do: figure out whose product is on the truck and split that number across those suppliers.

How the split works (auto):
  • Attribute — each transfer line's item → its Item Line → its Supplier (a real link, not a guess).
  • Allocate — split the freight by weight (configurable: weight → value → equal), so heavier product carries more freight.
  • Cover — apply each supplier's own coverage % to their slice.

Worked example — live-verified in the org

Gross shares sum to $1,000 exactly (penny-accurate). Each supplier gets their own billback; each line records the basis (Weight), the driver (lbs), and the share % — so you can see why each got their slice.

The config decision — Manual vs Partial (per org)

Auto-split is only as good as the item→supplier data. So it's a switch, not a hard rule:

Manual — safe default

You pick one Recoverable Freight Account; freight bills 100% to it. Exactly today's behavior. Use where item→supplier data isn't trusted yet.

Partial — auto + safety net

Auto-attributes & splits across suppliers; any items it can't resolve fall to the manual account (or are logged, never silently mis-billed). Flip to this where the data is clean.

The v1 posture: ship the capability, let the config decide per org. Start Manual, flip to Partial once item→supplier data is trusted. Nobody gets mis-billed in between. (A per-transfer override field lets AR force Manual on any single move.)

② Inbound POs — single supplier, simplest path

A PO already names its one supplier, so there's nothing to split. On the PO you set Recoverable Freight Cost and flip Supplier Owes Freight → a billback fires at that supplier's coverage %.

PO fees gap: the PO only carries freight — one lump. It has no place for tolls, taxes, or other fees. Any non-freight charge on an inbound shipment only enters the system through the receipt (Source 3), not the PO. And like transfers, if a toll is bundled into the PO's freight number, it rides along invisibly.

③ Inventory receipt fees — where itemized fees live

Fees discovered at receiving (against an inbound shipment) — this is the only place fees come in itemized. Each Inventory Receipt Fee has a Cost Type that maps to a billback charge type:

Cost Type → Charge Type

  • Freight / Shipping / Fuel Surcharge → Freight
  • Pallet → Pallet Tax
  • Storage / Service / Interest → Receipt Fee

How it fires

When a receipt is set to Complete, each fee becomes a billback line under the supplier — in real time, nightly batch as backstop. Live-verified: a receipt with 3 fees ($500 / $120 / $80) produced a 3-line billback.

This is why "fee visibility" already exists on the inbound side — the fees arrive itemized, so each becomes its own line you can see. Note: there is no "Toll" cost type — a toll would land under Freight or Misc., not as its own line.

The rollup — Supplier Owed dashboard

On any supplier's Account, the Supplier Owed tab answers "what does this supplier owe us, and why?" — every open billback line, grouped by charge type, with subtotals and a grand total. Rows flagged as possible double-recovery (a claim on the same shipment) are dimmed and excluded from the total by default, with a toggle to include them.

Verified rollup: Riverbend — Freight $1,060 · Pallet Tax $120 · Receipt Fee $40 → grand total $1,220, calculated (never hand-keyed).

⏭️ Deferred (correctly)

Freight composition / tolls — can't be shown: freight is a lump input on both transfers and POs, so there's nothing to break down. Tolls are usually baked into the carrier's freight number already. Needs an SME to confirm invoices are itemized before it's even a feature.

State-Line Tax recovery — a clean, additive next build. The tax is already computed on the transfer (Transfer_Group_Adjustment__c.Tax__c) and the billback slot is reserved — it just needs a generator wired in. Gated on one SME question: do suppliers actually owe the state-line tax?

Ship verdict: v1 captures the real dollars (freight across transfers + POs, itemized receipt fees), handles the multi-supplier reality, and rolls it up per supplier. The deferrals are either impossible-without-new-input (freight composition) or a clean bolt-on later (state-line tax). Not leaving recoverable money on the table.
